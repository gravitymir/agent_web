# Agent Web

<img src="static/agentron.svg" width="72" height="72" align="right" alt="Логотип Agentron">

> **Agentron (Ag) — единица объёма агентской работы**, не скорости (не токены/час — это была бы
> производительность, а не объём сделанного). По аналогии с кВт·ч: **1 Ag = 1 час активной сессии
> агента × 1 млн токенов**. Показываются **два варианта**:
> `Agentron = H × (Tᵢ + Tₒ) / 1 000 000` — реальная новая работа (вход + выход); и
> `Agentron·cache = H × (Tᵢ + Tₒ + T_кэш) / 1 000 000` — полная нагрузка с кэш-переотправками контекста
> (`cache_read + cache_creation`). Кэш-повторы обычно составляют львиную долю (~95 %+, на каждом шаге
> заново шлётся весь контекст), поэтому `·cache` бывает намного больше даже у небольшого чата.
>
> Считается **живьём, по каждому чату** — не разовый снимок: `H` копится из фактической
> длительности каждого хода (`result.duration_ms`), токены — из `.jsonl`/нативного стора чата. Видно
> в приложении: чистые и кешированные токены (`tokens` + `tokens·cache`), строкой `time` (H) и
> двумя строками Agentron — в бейдже токенов и в панели «Использование». Марка, логотип и полная
> спецификация единицы — [проект Agentron на
> GitHub](https://github.com/gravitymir/agentron) и [`docs/AGENTRON.md`](docs/AGENTRON.md); нюансы
> движка — в `AGENT.md`.

Веб-интерфейс к Claude на Rust + Axum: «десктопный Claude в браузере» — живой стриминг ответов,
список чатов и история, повтор (resume) прошлых сессий. Работает в **двух режимах**:

- **CLI-режим** (по умолчанию) — запускает официальный `claude` как подпроцесс в режиме
  `stream-json` и ретранслирует его события в браузер. Переиспользует нативное хранилище Claude
  Code (`~/.claude/projects/`), так что чаты из терминала видны в вебе — и наоборот.
- **Native engine** (`CWI_ENGINE=native`) — ходит **напрямую** в Anthropic-совместимый
  `/v1/messages` (Anthropic / Kimi / GLM), без Claude Code CLI. Полный контроль над инструментами,
  провайдерами и текстом размышлений.

Оба движка **эмитят одинаковые кадры событий**, поэтому фронтенд и WebSocket-слой в обоих режимах
одни и те же (см. [«Режимы»](#режимы) и `AGENT.md`).

История сборок и последних изменений — в [`CHANGELOG.md`](CHANGELOG.md).

## Возможности

- 💬 Живой стриминг ответа токен-за-токеном (WebSocket + `--include-partial-messages`)
- 🧵 Многоходовые диалоги с сохранением контекста (долгоживущий keeper-процесс на сессию)
- 🗂 Список чатов из истории, открытие и дозагрузка прошлых сессий; **поиск**, **удаление**,
  **экспорт в Markdown**
- ⬇️ Панель действий с чатом (кнопка со стрелкой справа, под шестерёнкой): экспорт в Markdown и
  JSON, архив файлов чата, удаление — выезжает справа, ничего не перекрывает переписку
- 🔄 Кнопка перезагрузки слева в капсуле заголовка — для мобильных, где переписка скроллится внутри
  контейнера и штатный pull-to-refresh недоступен
- 🆕 Создание чата через модалку: **своё название** + **иконка** из палитры
- ⚙️ Панель настроек (справа): **провайдер**, **модель**, **размер шрифта**, голосовой ввод —
  сохраняется в браузере
- 🧠 Сворачиваемый блок «Размышления» (thinking), свёрнутые чипы вызванных инструментов с diff
- 📝 Markdown с подсветкой синтаксиса, кнопкой «копировать» и **предпросмотром HTML** в sandbox —
  всё без внешних зависимостей
- 📎 Вложения: вставка картинок (Ctrl+V) и текстовых файлов (кнопка / drag-drop, инлайнятся в промпт)
- 🎙 Голосовой ввод (Web Speech API), 💲 токены/стоимость хода, ⏹ остановка генерации
- 🔐 Интерактивный **Allow/Deny** для инструментов в CLI-режиме — с панелью авто-одобрений по
  группам инструментов; уточняющие вопросы (`AskUserQuestion`) всегда идут пользователю на выбор,
  без авто-одобрения
- 🔔 Звук + системное уведомление по завершении хода (с превью ответа), не срабатывает на обрыв/
  перезапуск сервера
- 🔒 Отправка не теряется при обрыве связи: текст и вложения остаются в поле (заблокированном) до
  подтверждения сервером; при разрыве — просто разблокируются для повторной отправки
- ⭕ Индикатор заполненности контекста — кольцо, заполняющееся по часовой стрелке (как в
  интерактивном CLI), плюс сырые числа в панели «Использование»
- 📁 **Проводник** (третья кнопка слева): навигация по папкам рабочей директории, хлебные крошки,
  просмотр текстовых файлов. Только чтение и только внутри воркспейса; запуск файлов — не сделан

## Требования

- **Rust** (stable) + Cargo — для сборки.
- **Claude Code CLI** (`claude` в PATH, авторизованный) — для CLI-режима.
- **API-ключ провайдера** (Anthropic console / Kimi / GLM) — для native-режима.

## Сборка и запуск

```bash
cargo run                       # dev-сборка, слушает http://127.0.0.1:8787
```

Релизная сборка:

```bash
cargo build --release
./target/release/agent_web
```

Откройте <http://127.0.0.1:8787>.

Конфигурация читается из окружения и из файла `.env` в корне (грузится автоматически при старте;
переменные из окружения перекрывают файл). В репозитории лежит готовый шаблон
[`.env.example`](.env.example) — скопируйте его и впишите ключи:

```bash
cp .env.example .env            # затем отредактируйте .env (он в .gitignore)
```

Пример `.env` для native-режима (Kimi):

```dotenv
# Движок: native = встроенный агент /v1/messages; пусто/cli = Claude Code CLI
CWI_ENGINE=native

# Провайдер: anthropic | kimi | glm
CWI_AGENT_PROVIDER=kimi

# Ключи (нужен только ключ активного провайдера)
CWI_AGENT_KIMI_API_KEY=sk-...
CWI_AGENT_GLM_API_KEY=
CWI_AGENT_CLAUDE_API_KEY=

# Показывать размышления, где провайдер поддерживает
CWI_AGENT_THINKING=1

# Необязательные переопределения:
# CWI_AGENT_MODEL=kimi-k2.7-code
# CWI_AGENT_BASE_URL=
# CWI_AGENT_MAX_TOKENS=8192
# CWI_BIND=127.0.0.1:8787
```

Для CLI-режима `.env` не обязателен — достаточно авторизованного `claude` в PATH.

| `CWI_ENGINE`          | *(пусто)* → CLI    | `native` включает native engine                    |
| `CWI_STATIC_DIR`      | `static`           | Папка со статикой фронтенда                         |
| `CWI_ENV_FILE`        | `.env`             | Путь к env-файлу, который грузится при старте       |
| `RUST_LOG`            | `info`             | Уровень логирования                                |

### CLI-режим

| Переменная            | По умолчанию   | Назначение                                             |
|-----------------------|----------------|--------------------------------------------------------|
| `CWI_CLAUDE_BIN`      | `claude`       | Путь/имя исполняемого файла Claude Code                 |
| `CWI_PERMISSION_MODE` | `default`     | Режим прав (`default`, `acceptEdits`, `bypassPermissions`, …) |

> **Права инструментов.** По умолчанию — `default`: любой инструмент, которому нужно решение
> (Write/Edit, Bash, WebFetch, WebSearch, `AskUserQuestion`), идёт через `--permission-prompt-tool
> stdio` и реально гейтится панелью «Инструменты и разрешения» (см. `AGENT.md`). `Read`/`Glob`/`Grep`
> Claude Code не гейтит ни в одном режиме — это не наша настройка. `acceptEdits`/`bypassPermissions`
> **обходят** наш гейт для соответствующих групп на уровне самого CLI, ещё до того, как решение
> дойдёт до приложения — задавайте их, только если сознательно не хотите панель разрешений.

### Native engine

| Переменная                | По умолчанию                 | Назначение                                            |
|---------------------------|------------------------------|-------------------------------------------------------|
| `CWI_AGENT_PROVIDER`      | `anthropic`                  | Пресет: `anthropic` \| `kimi` \| `glm` \| `gemini`    |
| `CWI_AGENT_API_KEY`       | —                            | API-ключ (общий; перекрывает ключ конкретного провайдера) |
| `CWI_AGENT_CLAUDE_API_KEY`| —                            | Ключ Anthropic (нужен **console**-ключ, не подписка)  |
| `CWI_AGENT_KIMI_API_KEY`  | —                            | Ключ Kimi (Moonshot)                                  |
| `CWI_AGENT_GLM_API_KEY`   | —                            | Ключ GLM (Z.ai)                                       |
| `CWI_AGENT_GEMINI_API_KEY`| —                            | Ключ Gemini (Google AI Studio; см. ниже)              |
| `CWI_AGENT_MODEL`         | по провайдеру¹               | Переопределить модель                                 |
| `CWI_AGENT_BASE_URL`      | по провайдеру²               | Переопределить базовый URL                            |
| `CWI_AGENT_MAX_TOKENS`    | `8192`                       | Лимит выходных токенов                                 |
| `CWI_AGENT_THINKING`      | вкл. у Anthropic/Gemini, иначе выкл. | Показывать размышления (где поддерживается)   |
| `CWI_MCP_CONFIG`          | `~/.claude/cwi_mcp.json`     | Конфиг MCP-серверов (см. ниже)                        |

¹ дефолт модели: `claude-opus-5` (anthropic), `kimi-k2.7-code` (kimi), `glm-5.2` (glm),
`gemini-pro-latest` (gemini — плавающий алиас на текущую рекомендованную модель, а не жёстко
зафиксированная версия: у Gemini они меняются быстро).
² дефолт URL: `https://api.anthropic.com`, `https://api.moonshot.ai/anthropic`,
`https://api.z.ai/api/anthropic`, `https://generativelanguage.googleapis.com` соответственно.

> **Gemini — не Anthropic-совместимый.** В отличие от Kimi/GLM (которые отдают тот же
> `/v1/messages`-формат, что и Anthropic, и включаются просто сменой URL/ключа), у Gemini свой
> формат запросов/ответов, свой стриминг и вызов инструментов без стабильного id у tool-call.
> Поддержка реализована через отдельный адаптер-переводчик (`src/agent/gemini.rs`), а не через
> ещё один пресет — детали в `AGENT.md`. Ключ — обычный платный API-ключ
> ([aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)); подписка Google AI
> Pro/Ultra API не покрывает — она даёт лимиты только в Gemini CLI (и с 18 июня 2026 без биллинга
> даже там сильно урезана).

## Режимы

**CLI-режим** (по умолчанию) запускает
`claude --print --output-format stream-json --input-format stream-json --include-partial-messages
--verbose`, кормит ходы через stdin и читает события из stdout. Требует установленного и
авторизованного `claude`. История берётся из `~/.claude/projects/`.

**Native engine** (`CWI_ENGINE=native`) обращается напрямую к `/v1/messages` выбранного провайдера
и сам гоняет agent-loop (модель → `tool_use` → выполнение инструмента → `tool_result` → повтор).
Claude Code CLI не нужен. Свои сессии хранятся в `~/.claude/cwi_native/<id>.json` (отдельно от
CLI-формата). Инструменты (Bash/Read/Write/Edit/Glob/Grep, песочница ограничена рабочей папкой) плюс
MCP. Ключ Anthropic должен быть **console**-ключом — токен подписки на `/v1/messages` даёт 401.

## MCP (только native engine)

Native engine может подключать внешние [MCP](https://modelcontextprotocol.io)-серверы по stdio.
Конфиг — `~/.claude/cwi_mcp.json` (или `CWI_MCP_CONFIG`). Их инструменты видны агенту как
`mcp__<server>__<tool>`. Пример:

```json
{
  "servers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/workspace"]
    }
  }
}
```

Отсутствующий/битый конфиг — просто нет MCP-серверов (без ошибки). stderr серверов дренажится в лог.

## Изолированный executor (брокер + одноразовая VM)

Агента можно гонять в **одноразовой VirtualBox-машине**, чтобы реальный API-ключ
никогда не покидал хост. Хост держит «брокер» (прокси с настоящим ключом и
короткоживущими session-токенами), а гостевой `agent_web` ходит за инференсом на
брокер, предъявляя токен вместо ключа. Управление — на главной странице, вкладка
слева **«Гостевой сервер»** (Start / Stop / **Drain-Stop** — мягкая остановка,
дожидающаяся активных гостевых сессий), по WebSocket.

- Токены брокера: `agent_web broker <new|list|revoke>` (TTL + бюджет, на диск — только SHA-256).
- Одноразовый цикл: `restore clean` → холодный буст → systemd `agent-web` встаёт сам (~12 с).
- Для боевого прогона выбери на хосте движок **«Native — Anthropic API»** (брокер форвардит в Anthropic-формате).
- Гостевые доступы — вкладка **«Ссылки»** на мастер-странице: выпуск/список/отзыв
  magic-link'ов (валидируются на executor'е, коды пушатся туда с хоста).

Полное описание — архитектура, провижнинг снапшота `clean`, семантика Drain-Stop,
пере-провижнинг — в [`docs/EXECUTOR.md`](docs/EXECUTOR.md); подъём «наружу»
(Cloudflare-туннель, admin/guest домены, go-live) — в [`docs/GO_LIVE.md`](docs/GO_LIVE.md).

## Безопасность

По умолчанию приложение слушает `127.0.0.1` **без аутентификации** — это локальный инструмент, через
который можно выполнять код и читать/писать файлы воркспейса. Прежде чем биндить не-loopback адрес,
включите встроенный гейт `CWI_AUTH=1` (HMAC-cookie + одноразовые коды, rate-limit, разделение
admin/guest), а для чужих рук — ещё и [изолированный executor](#изолированный-executor-брокер--одноразовая-vm).

Что уже реализовано (гейт, SSRF-контур WebFetch с пином адреса и проверкой каждого редиректа,
валидация id, CSP, лимиты) и что осталось — в [`docs/HARDENING.md`](docs/HARDENING.md).

## Архитектура

```
        ┌──WebSocket──►  Axum  ──► SessionKeeper ──stdin/stdout(stream-json)──► claude
Браузер ┤ (attach)          (broadcast + scrollback, живёт независимо от соединений)
        └──REST /api/chats─► читает ~/.claude/projects/*.jsonl
```

Каждая сессия принадлежит **keeper-процессу** (`SessionKeeper`), который владеет подпроцессом
`claude` и **живёт независимо от WebSocket**. Это даёт:
- процесс **переживает** обрыв соединения и перезагрузку страницы (задача не прерывается);
- **мультиклиент**: несколько вкладок/устройств подключаются к одной сессии и видят ходы друг
  друга (события раздаются через `broadcast`-канал);
- **scrollback**-буфер (до 3000 событий): (пере)подключившийся клиент реплеит живую сессию, а не
  видит пустой экран;
- эхо пользовательских ходов (`{"cwi":"user"}`) — все зрители и реплей видят и запросы, и ответы.

Idle-keeper (нет зрителей 30 мин) отправляется в утиль фоновым reaper'ом.

| Файл                | Роль                                                        |
|---------------------|-------------------------------------------------------------|
| `src/main.rs`       | Роутер Axum, состояние, REST-эндпоинты                      |
| `src/config.rs`     | Конфиг из env, кодировка пути проекта → папка сессий         |
| `src/claude.rs`     | Запуск подпроцесса `claude` (`spawn_claude`)                 |
| `src/session.rs`    | `SessionManager` + `SessionKeeper` (broadcast, scrollback, reaper) |
| `src/ws.rs`         | WebSocket: подключение (attach) к keeper'у, ретрансляция     |
| `src/history.rs`    | Парсинг `~/.claude/projects/*.jsonl` (список и транскрипты)  |
| `src/titles.rs`     | Свои метаданные чатов (название + иконка) в `~/.claude/cwi_titles.json` |
| `src/models.rs`     | Список моделей Claude (Models API + суточный кэш)            |
| `src/agent/`        | Native engine: `mod.rs` (agent-loop), `provider.rs`, `client.rs` (SSE), `tools.rs`, `store.rs`, `mcp.rs` |
| `static/`           | Фронтенд: `index.html`, `styles.css`, ES-модули в `static/js/` (`state.js`, `render.js`, `ws.js`, `ui.js`, `main.js`) |

### Названия и иконки чатов

Файлы сессий (`.jsonl`) ведёт сам Claude Code — мы их не трогаем. Пользовательские названия и иконки
хранятся отдельно в `~/.claude/cwi_titles.json` (карта `session_id → { title, icon }`) и накладываются
поверх авто-заголовка при выводе списка. Название и иконка задаются при **создании** чата; клиент сам
генерирует `session_id` (UUID) и помечает первый ход как новый (`new_chat`), чтобы бэкенд использовал
`--session-id`, а не `--resume`. Эндпоинт `PUT /api/chats/{id}/meta` принимает `{ title, icon }`.

### Протокол WebSocket

Клиент → сервер:
```json
{ "type": "send", "session_id": "<uuid|null>", "text": "…", "model": "opus", "new_chat": true }
{ "type": "attach", "session_id": "<uuid>" }
{ "type": "interrupt" }
{ "type": "permission_response", "request_id": "…", "allow": true,
  "answers": { "вопрос": "выбранный вариант" } }
{ "type": "permission_response", "request_id": "…", "allow": true,
  "response": "свободный текст" }
```
- `new_chat: true` — первый ход только что созданного (уже названного) чата: бэкенд стартует его
  через `--session-id`, а не `--resume`.
- `attach` — (пере)подключиться к живой сессии; keeper реплеит scrollback.
- `permission_response` отвечает на `permission_request` (см. ниже): `answers` — выбор варианта(ов)
  для `AskUserQuestion`; `response` — альтернативный свободный ответ на всю карточку целиком
  (взаимоисключим с `answers`). Для обычных инструментов достаточно `allow: true|false`.

Сервер → клиент: сырые события `stream-json` от Claude плюс управляющие кадры с полем `cwi`:
- `{ "cwi": "session", "session_id", "replay" }` — назначен/возобновлён id; `replay:true` → клиент
  очищает вид и перестраивает его из следующего дальше scrollback;
- `{ "cwi": "user", "text" }` — ход пользователя (эхо для всех зрителей);
- `{ "cwi": "exit" }` — процесс завершился; `{ "cwi": "no_session" }` — нечего подключать;
- `{ "cwi": "error", "message" }`;
- `{ "cwi": "permission_request", "request_id", "tool_name", "input" }` — CLI спрашивает разрешение
  на инструмент (или это `AskUserQuestion`), и панель авто-одобрений его не закрыла — рисуется
  интерактивная карточка Allow/Deny (или карточка вопроса с вариантами + свободным ответом);
- `{ "cwi": "permission_resolved", "request_id", "allow", "answers", "response" }` — запрос выше
  получил ответ (от этого или другого зрителя).

## Дальнейшие шаги (roadmap)

Цель — управлять сессиями Claude Code удалённо, «из кармана» (по мотивам разбора видео):

1. ✅ **Keeper-процессы** — процесс переживает разрывы, мультиклиент, scrollback *(готово)*.
2. **Web Push + удалённые разрешения** — control-протокол разрешений инструментов (`can_use_tool`)
   уже реализован (см. [«Протокол WebSocket»](#протокол-websocket)) *(готово)*; остаётся хук
   запрос/завершение → пуш-уведомление на телефон, ответ из шторки без открытой вкладки.
3. **QUIC / WebTransport** — удалённая достижимость. Нюанс: из браузера это WebTransport (HTTP/3),
   он решает транспорт, но не пробитие NAT — понадобится релей или частично-нативный компаньон.
4. Модель безопасности для выхода за localhost: TLS + cert pinning (TOFU), одноразовый QR/код,
   rate-limit, closed-by-default allowlist.

Готово попутно: поиск/удаление/экспорт чатов, вложения файлов, голосовой ввод (Web Speech API),
подсветка синтаксиса и предпросмотр HTML, native engine с MCP, интерактивный Allow/Deny +
`AskUserQuestion`, звук/уведомления по завершении хода, устойчивая к обрыву связи отправка,
**изолированный executor** — брокер с реальным ключом на хосте + одноразовая VM с управлением
из вкладки «Гостевой сервер» (см. [`docs/EXECUTOR.md`](docs/EXECUTOR.md)).

Прочее (планы): мультиворкспейсы, рендер результатов инструментов в истории, компакция контекста и
листинг native-чатов в сайдбаре, локальный Whisper вместо Web Speech API.

## Файлы вне репозитория (локальные)

Эти файлы **не** коммитятся в Git (они машинно-локальные, содержат состояние или
чувствительные данные) — здесь их полная структура, чтобы восстановить/понять из любой сессии.

### `.claude/settings.local.json` — локальные настройки Claude Code *(в `.gitignore`)*

Разрешения инструментов Claude Code для этого проекта на **данной машине** (allow/deny-списки
команд). Не влияет на само веб-приложение; нужен только при разработке через Claude Code.

```json
{
  "permissions": {
    "allow": [
      "Bash(cargo --version)",
      "Bash(rustc --version)",
      "Bash(claude --version)"
    ],
    "deny": []
  }
}
```

Восстановление: файл не обязателен — Claude Code пересоздаст его сам, спрашивая разрешения по
ходу. Можно просто создать с пустым `"allow": []` или скопировать пример выше.

### `~/.claude/cwi_titles.json` — названия и иконки чатов *(создаёт приложение)*

Карта `session_id → { title, icon }`. Накладывается поверх авто-заголовка при выводе списка
(см. `src/titles.rs`). Путь: `<домашняя>/.claude/cwi_titles.json`.

```json
{
  "aebdc183-eb43-4a07-9224-eb7c9c7534b1": {
    "title": "Рефакторинг API",
    "icon": "🚀"
  }
}
```

- ключ — UUID сессии (совпадает с именем `<uuid>.jsonl` в `~/.claude/projects/...`);
- `title` — строка (пустая ⇒ используется авто-заголовок);
- `icon` — emoji-строка или `null` (без иконки).

Восстановление: создаётся автоматически при первом переименовании/создании чата. Можно удалить —
чаты просто вернутся к авто-заголовкам.

### `~/.claude/cwi_models.json` — кэш списка моделей *(создаёт приложение)*

Кэш ответа Anthropic Models API (см. `src/models.rs`). Обновляется не чаще раза в сутки.

```json
{
  "fetched_at": 1785610051,
  "models": [
    { "id": "claude-opus-5", "display_name": "Claude Opus 5" },
    { "id": "claude-sonnet-5", "display_name": "Claude Sonnet 5" }
  ]
}
```

- `fetched_at` — Unix-время (сек) последнего успешного запроса; свежесть проверяется по TTL 24 ч;
- `models` — массив `{ id, display_name }`.

Восстановление: не нужно — удали файл, и он перезапишется при следующем `/api/models`.

### `~/.claude/cwi_native/<uuid>.json` — сессии native engine *(создаёт приложение)*

Хранилище чатов native-режима (массив `messages` в формате Anthropic + название/модель/токены,
см. `src/agent/store.rs`). Отдельно от CLI-формата `.jsonl`. Восстановление не нужно — создаётся
на первый ход native-чата; удаление файла стирает чат.

### `~/.claude/cwi_mcp.json` — конфиг MCP-серверов *(создаёте вы, native engine)*

Список stdio MCP-серверов (см. раздел [«MCP»](#mcp-только-native-engine)). Опционален: без него
MCP-инструментов просто нет.

### `~/.claude/.credentials.json` — OAuth-токен Claude Code *(владелец — Claude Code, только читаем)*

Мы **не создаём** и **не коммитим** этот файл — им владеет Claude Code. Бэкенд лишь **читает**
из него `claudeAiOauth.accessToken`, чтобы обратиться к Models API от имени пользователя. Форма
(упрощённо):

```json
{
  "claudeAiOauth": {
    "accessToken": "<короткоживущий OAuth-токен>",
    "refreshToken": "…",
    "expiresAt": 0,
    "scopes": ["…"],
    "subscriptionType": "…"
  }
}
```

Восстановление: создаётся командой `claude auth login` (подписка Claude). Секрет — **никогда**
не коммитить и не выводить.

### `~/.claude/projects/<encoded>/<uuid>.jsonl` — история чатов *(владелец — Claude Code)*

Транскрипты сессий, которые ведёт сам Claude Code (по строке-событию на строку). Мы их только
**читаем** для списка чатов и истории (`src/history.rs`), никогда не пишем. `<encoded>` — путь
рабочей папки, где каждый не-алфацифровой символ заменён на `-`.

### `/target` — сборка Cargo *(в `.gitignore`)*

Артефакты компиляции. Пересоздаётся `cargo build` / `cargo run`.
